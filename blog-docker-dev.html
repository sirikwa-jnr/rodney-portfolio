Why I Started Using Docker in VS Code for My Projects

By Rodney Achota · 2026 · 5 min read

When I built my To-Do List app and my Calendar app, I did something that changed how I develop: I ran them inside Docker containers, developed in VS Code, and kept everything reproducible on any machine.

The Problem Docker Solves

Before Docker, every project came with the classic question: "It works on my machine — why not yours?" Docker packages your app and its entire environment into a single container.

What I Actually Did

For each project, I created a small Dockerfile and a docker-compose.yml inside VS Code. Then I used the Dev Containers extension to develop inside the container.

# Dockerfile (simplified)
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["npm", "start"]
      
# docker-compose.yml (simplified)
version: '3.9'
services:
  app:
    build: .
    ports:
      - "3000:3000"
    volumes:
      - .:/app

From VS Code, I just run:

docker compose up --build

And the app runs — identically, every time.

Why This Changed My Workflow

  • Consistency: Same environment on any machine
  • Isolation: One project's dependencies don't break another's
  • Clean machine: No global installs — everything lives in the container
  • Easy sharing: A teammate only needs the repo and Docker
  • Closer to production: Vercel, Railway and AWS all speak Docker
Docker doesn't just run my code — it documents the environment my code needs.

What I Plan Next

  • Publish the To-Do List and Calendar projects on GitHub with Dockerfiles
  • Deploy them to a cloud provider that supports Docker
  • Learn Kubernetes (the next logical step)
